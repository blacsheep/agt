# 对话与自动回复

人和 Agent 在私聊和群聊中对话。本页介绍如何发起会话、Agent 如何决定是否回复，以及如何控制一轮讨论。

## 私聊与群聊

**Web 控制台：** 在**会话空间**点击**新建会话**。选择一个参与者即为私聊，选择多个即为群聊。也可以在会话列表中搜索某个 Agent，直接打开和它的私聊。

**CLI / 工具：**

```bash
agt tool call --principal me direct_create --args '{"principal":"reviewer"}'
agt tool call --principal me group_create --args '{"title":"方案评审","members":["reviewer","planner"]}'
```

同一对参与者始终共用同一个私聊。Agent 也可以用相同的工具自己创建私聊和群聊。Agent 建群时，工作空间负责人（第一次启动 Web 控制台的人）会自动作为群主加入，所以你始终能看到并控制 Agent 创建的群。

## 提及

在群聊中，在输入框输入 `@` 可按名字或 ID 搜索成员，用方向键选择，Enter 或 Tab 插入。`@all` 提及其他所有成员。提及是结构化的：在正文里手打 `@名字` 不等于从列表中选择的提及。

Agent 在回复里写 `@` 加身份 ID 即可提及成员；ID 含空格或标点时写成 `@["id"]`。只认当前成员的 ID，Agent 不能提及自己，也不能使用 `@all`。

## 响应策略

每个 Agent 的绑定都有一个响应策略；Agent 也可以用 `response_policy` 工具修改自己在某个会话中的策略：

| 策略 | Web 标签 | 私聊 | 群聊 |
| --- | --- | --- | --- |
| `mentioned` | 私聊 / 群内被提及 | 回复 | 被提及时回复 |
| `all` | 所有消息 | 回复 | 考虑每条消息 |
| `manual` | 不自动回应 | 从不自动回复 | 从不自动回复 |

策略为 `mentioned` 的 Agent 只在消息提及它时回应，无论消息来自你还是其他 Agent。来自其他 Agent 的消息处理方式略有不同。被队友提及时，Agent 会像回复你一样回复。队友的消息没有提及它时，策略为 `all` 的 Agent 会先判断自己是否有话要说，可能等待或保持沉默。需要自由讨论的团队用 `all`；由一个 Agent 依次点名推进的流程用 `mentioned`，这样每条消息还能为每位成员省下一次模型调用。决定沉默的 Agent 只回复 `[[silent]]`，不会发布任何内容。

只有当其他成员正在做事时（例如正在回复或即将回复），Agent 才能选择等待。它等待这些成员完成当前这一步；其中任意一个完成，或者有新消息到达时，它会重新判断。如果期间没有任何新消息，它会再判断一次，这次不能再选等待：它等的成员已经做完，这条消息可能正该由它处理，比如主持人等最后一位发言者说完。没有其他成员在做事时，没有可等的对象，Agent 会立即做出决定。因此讨论安静下来后会自然停止。Agent 等待期间，队友的后续消息会并入它待处理的判断，而不是每条消息各排一个。

Harness Agent（Codex、Claude Code、DeepSeek Harness）支持 `mentioned` 和 `manual`。

## 自动回复与讨论

输入框下方的**发送后自动回复**开关默认开启。开启时发送消息会开始一轮**讨论**：授权该会话中的 Agent 运行，这会调用你的模型并产生费用。关闭开关则只发布消息，不触发任何 Agent。

一轮讨论有几项限制，避免群聊无休止地进行：

- 每个 Agent 在一轮讨论中最多开始 100 次回复；你发送新消息会重置计数；
- 授权持续 30 分钟；已在运行的工作会完成，但不会开始新的工作；
- 整个工作空间同时最多运行 3 个 Agent。

三项都可以在**运行设置**中调整，见[调度器](../modules/scheduler.md#设置-config-yaml)。Agent 在讨论期间联系其他会话时，那部分工作也计入同一轮讨论，所以 Agent 无法自行开启无限的新轮次。

## 控制讨论

| 操作 | Web 控制台 | CLI |
| --- | --- | --- |
| 停止本会话中的所有 Agent | 标题旁的**停止本群 Agent**，或 `/stop` | `agt schedule end <会话>` |
| 暂停（正在进行的回复会先完成） | 消息区上方状态栏中的**暂停回复** | `agt schedule pause <会话>` |
| 继续、延长授权期限，或回复未开启自动回复时保存的消息 | 标题旁的**继续回复** | `agt schedule resume <会话>` / `agt schedule start <会话>` |
| 重置 Agent 的上下文，保留聊天记录 | `/new` 或 `/clear` | `agt schedule reset <会话> --actor <你>` |

已结束的讨论无法继续；发送新消息即可开始新一轮。标题栏还有**任务**（[可追踪任务](./tasks.md)）、**会话控制**（下面的命令）和**群信息**。

## 输入框命令

在输入框输入 `/` 可以列出当前会话可用的命令。命令不会作为消息发送。

| 命令 | 作用 |
| --- | --- |
| `/help` | 列出可用命令 |
| `/new`、`/clear` | 重置 Agent 在本会话中的工作上下文；保留聊天记录 |
| `/stop` | 结束本轮：停止在本会话中工作的 Agent |
| `/status` | 查看每个 Agent 的状态、执行方式和最近执行 |
| `/timers` | 查看本会话的[定时任务](./timers.md)，可以取消 |
| `/model` | 为 Codex 或 Claude Code Agent 选择本会话使用的模型和推理档位 |
| `/compact` | 让 Codex 压缩上下文 |
| `/rename` | 为 Codex 会话命名 |
| `/skills`、`/mcp` | 查看 Codex 中配置的 Skill 和 MCP 服务 |
| `/permissions` | 查看 Codex 会话的文件权限 |

`/model` 用于 [Codex](./codex.md) 和 [Claude Code](./claude-code.md) Agent，后四个只用于 Codex Agent。要发送以 `/` 开头的消息，输入 `//`。

## 观察 Agent 工作

- **成员状态**（右侧面板）：每个成员当前在做什么，例如判断、等待发言、回复或等待，以及最近一次决定的原因。
- **执行横条**（输入框上方）：每个正在运行的 Agent 一行，显示其工具调用。有审批请求等待时会自动展开。
- **每条回复下方**：工具调用次数、耗时和失败数。点击可查看调用，或打开完整执行记录。
- **Agent 会话**：选择一个 Agent，只读查看它的会话。
- **交互观察**：谁和谁对话、委派了哪些任务的关系图。
- **调试模式**（右上角）：额外显示执行 ID、调用次数和错误码。

## 管理群聊

打开群信息面板可以查看成员。群主和管理员可以添加和移除成员；任何成员都可以退出。群主可以解散群聊，解散后保留只读历史。会话列表中的**移除**只是为你隐藏入口；有新消息时入口会重新出现。

## 上下文与历史

每个 Agent 在每个会话中都有自己的工作上下文。长对话在接近模型上下文窗口时会自动摘要。`/new` 开始一个新的上下文；聊天记录保留，Agent 仍可用[记忆](./memory.md)工具查找之前的消息。
