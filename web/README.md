# AGT Studio · 本地交互控制台

现行使用说明 · 2026-09-08。无需安装前端依赖。需要 Node.js 22+、
Rust 1.96.1+，以及本仓库构建出的 CLI。[全部文档](../docs/README.md)。

## 启动

在仓库根目录执行：

```bash
cargo build -p agt-cli
node web/server.mjs
```

Windows PowerShell：

```powershell
cargo build -p agt-cli
node web/server.mjs --binary .\target\debug\agt.exe
```

Node 同时提供前端页面和 HTTP 接口，并启动 Rust 调度进程。
更新代码后重新构建 CLI、重启 Web，再刷新页面。若使用自定义 `--binary`，
请确认它也已更新，否则可能出现 `schedule` 命令不可用。

打开终端打印的**完整链接（包括 `#` 后的令牌）**。默认端口 4317，读取
`~/.agt`；首次启动会创建 `web-operator` 用户身份，不会为旧消息擅自调用模型。
服务会启动后台调度器；之前已授权但尚未完成的讨论和提醒可在重启后继续。
已有资源不会被启动流程覆盖。服务器重启后，请使用新的完整链接。

可选择隔离的资源目录或其他端口：

```bash
node web/server.mjs --home /absolute/path/to/test-home --port 4318
```

`--binary /absolute/path/to/agt` 可指定其他 CLI，`--principal my-operator`
可指定本地用户身份。空目录会初始化；不要把正式目录当作无副作用的演示环境。

远程服务器仍只监听服务器自己的 `127.0.0.1`。需要从本机浏览器使用时，可通过
SSH 本地转发（本机端口也使用 4317）：

```bash
ssh -N -L 4317:127.0.0.1:4317 user@server
```

随后打开远程终端提供的完整 `http://127.0.0.1:4317/#令牌` 链接。
自定义端口时两端保持一致，不要直接代理到公网；令牌等同主机管理权限。

## 工作区布局

左侧默认显示紧凑图标导航，顶部菜单按钮可展开名称。会话页的“会话列表”和
“成员状态”可分别收起，让聊天区占用更多空间；浏览器会记住这三个布局选择。
收起面板不会停止调度、清空输入或关闭已展开的成员说明。

Agent 卡片保留“编辑角色”和“发起私聊”常用操作；托管设置、资源查看和删除
位于“配置与管理”展开区。成员状态下的“最近动态”也按需展开。

## 自己验收：准备 → 对话 → 执行 → 观察

1. **资源库准备模型**：已有 Provider 和模型会直接列出。支持 Chat Completions
   和 Responses；新建模型时选择 Provider 实际支持的 API 协议和模型名称。
   Provider 直接输入 API Key，Web 不提供环境变量配置方式。
   新建模型时，选择 Provider 并点击“获取模型列表”，即可从返回列表选择模型；
   列表不可用时仍可手动填写。新建模型不指定输出 token 上限，已有模型配置不变。
   已有 Responses 模型可直接用于角色，无需创建 Chat Completions 别名。
2. **Agent 团队创建角色**：选择模型、填写职责 Prompt，按需挂载 Skills/MCP。
   默认策略为“私聊 / 群内被提及”。可创建主持人、研究员、反方等通用角色，
   没有游戏专属层。创建失败会显示已完成步骤；已创建字段锁定，后续步骤可修正重试。
   要让角色管理资源，在“框架内置工具”中勾选“资源管理”，保存后直接对话即可。
   已有角色可通过“编辑角色”添加或取消挂载。无需创建外部 MCP 或运行 agt serve。
   这会授权管理当前 home 全部六类资源，包括其他 Agent 定义与按计划删除依赖者；
   同时授予 Agent 聊天身份创建、运行设置及启用／停用管理；不能创建普通用户身份。默认资源和运行配置删除保护仍然生效。
   MCP 按 Agent 装配加载，具体调用仍经过权限审批；模型须支持工具调用，且响应策略不能是“不自动回应”。
   取消挂载在下一次运行生效，已开始的运行使用原快照。
3. **新建会话**：私聊选择一位参与者；群聊选择多位参与者。群消息广播给成员，
   输入 `@` 按名字或身份 ID 搜索成员，用方向键选择、Enter/Tab 插入、Esc 关闭。
   `@all` 提及当前会话除自己外的所有成员；删除提及文字即取消邀请。
   不写提及时按原有响应策略处理；是否实际执行仍取决于托管、授权与响应策略。
4. **发送任务**：输入框默认开启“发送后自动回复”，发送成功后会调用模型，
   可能产生费用；关闭开关则只保存消息。仅显式授权的用户消息开启讨论；
   Agent 主动联系其他会话时继承原讨论的回复计数，不会开启无限的新轮次。
5. **回复与暂停**：不同托管身份可并行执行（默认最多 3 个），同一 principal 跨会话
   仍一次只处理一项任务；多个身份绑定同一个 Agent 定义仍可并行。
   未被点名的同伴消息先判断参与、沉默或等待；用户消息和明确点名的同伴消息
   绕过参与判断，仍受响应策略约束。计时提醒会持久化，
   消息独立入队，不再固定等待 5 秒。Native 运行中按 steering / follow-up 边界接收同会话输入。
   不同 Agent 可并行判断；决定参与后等待回复名额，自主接话依次开始。
   等待名额不占线程，轮到发言时若有新消息会重新判断，避免重复回答。
   每位 Agent 最多开始 100 次回复，新的用户消息获准自动回复后计数归零。
   不再限制整轮模型调用或判断次数。暂停让当前回复完成；“结束讨论”取消后续回复和提醒。
   “继续回复”恢复处理或续期，不重置回复计数。失败/中断且可能已有副作用的操作不会重跑。
   Web 新建绑定默认每次运行最多 8 个模型步骤，响应策略仍然生效。
   已全局取消自动消息深度限制；绑定只使用当前字段。
6. **查看结果**：会话顶部汇总成员进度，侧栏“成员状态”分别呈现当前调度状态与最近模型决定。
   点击成员行展开原因、决定时间及等待条件；说明默认两行预览，轮询保留展开与焦点。
   来源区分模型自主、框架调度/规则及暂停操作；结果或异常不会假装成模型判断。
   模型可提供最多 240 字符的公开决策说明，不采集隐藏推理；旧记录不补造说明。
   “无追加回复”可能是工具已发送消息，不等于模型决定不参与。新消息触发重评估时保留旧决定并提示。
   手机和平板也可查看完整成员列表。消息下方“回复情况”和“最近动态”说明执行结果。
   右上角开启“调试模式”（debug_mode）后显示 Run、调用次数、参数形状及错误码；
   此开关仅影响展示，默认关闭，并记住当前浏览器的选择，不改变权限或日志采集。
   左侧先选择用户或 Agent，再进入该成员的会话列表，点击会话查看记录。
   操作员可发送消息；其他成员的会话仅供查看，不会代替他们发送。
   连续发送的新消息会排队处理；失败或已跳过的消息不会自动重跑。
7. **会话与群聊**：“移除”仅隐藏自己的入口，新消息可使仍在群内的入口重新出现。
   从“我的群聊”或“全部历史”可重新打开。群信息抽屉中，成员可退出并保留旧历史，
   群主可永久解散；退出期间的消息在重新入群后也不可见。解散保留只读记录。
   “停止本群 Agent”固定放在会话标题旁，暂停和继续保留为次级操作。
8. **Agent 会话**：先选择 Agent，再只读查看它的对话。会话空间始终是你的身份。
   Web 首次启动固定当前人为工作空间负责人，Agent 建群会自动加入该负责人为群主；
   创建者 Agent 为管理员。后续请使用同一负责人启动。CLI 可用
   `agt im owner ensure <user>` 初始化、`agt im owner get` 查询。

第一次可把角色策略设为“不自动回应”，验证发消息和投递的 skipped 状态，
确认操作熟悉后再改为“私聊 / 群内被提及”。已跳过的消息不会因修改策略自动重放，
请发送一条新消息测试真实模型。

## 常见问题

- **没有回复，也没有 Run**：先看回复动态，可能尚未授权、正在等待或无需参与；再检查托管绑定、manual 策略与邀请回应。
- **回复服务未连接**：核对 CLI 路径/版本，检查调度进程和目录权限，再重启。
  异常退出后租约通常最多约 15 秒过期，实际恢复还受进程启动与存储状态影响。
- **显示已达上限**：每位 Agent 达到 100 次回复后，发送新的用户消息并开启自动回复可重置。
  “继续回复”只恢复处理或更新期限。结束的讨论需发送新消息开启新轮。
- **看不到技术错误**：开启右上角调试模式；CLI 可用
  `agt --home DIR --output json schedule status` 和 `agt --home DIR run info RUN_ID`。
- **停止后没有继续回复**：停止已结束原讨论，移除或恢复入口不会重启讨论，请发新消息。

## 安全和当前范围

- 这是**可信本机管理控制台**，不是多用户登录系统。令牌持有者能管理资源和
  观察不同身份的私聊；不要分享链接、代理到公网或交给不可信网页使用。
- 服务仅监听 `127.0.0.1`，校验 Host、Origin 和 API 令牌；通过参数数组调用
  CLI，不拼接 shell 命令。Provider 在密码框中直接输入 API Key。
  输入的密钥通过单次 CLI 子进程环境传递，
  不进入命令行参数；密钥保存于本机 Provider 配置，列表和详情不会返回密钥。
- MCP 使用范围由 Agent 装配决定，具体调用仍经过权限审批。只挂载可信 MCP，它可能访问文件、网络或外部系统；
  已发送的外部请求可能在结束讨论后完成，不能保证撤回。
- 每个 home 只有一个活跃协调者；任务、提醒和预算
  保存在 `runtime/runtime.db`。Web 不再维护进程内串行队列。
- 后台持续监听不等于无限推理：每位 Agent 有 100 次回复上限，讨论有 30 分钟期限；单次运行的步数限制仍生效。
  异常重启最多等待约 15 秒接管租约；等待任务可恢复，结果不确定的响应标记为
  `interrupted`，请先检查 Run 和外部结果，不要盲目重放。
- `completed` 只表示运行结束，不保证所有工具成功或目标达成。调用记录仅包含
  参数形状和安全错误，不包含模型推理、原始参数或工具返回正文。
- 当前页面支持新建、查看和删除六类资源，以及更新或停止托管、私聊/群聊、
  个人会话隐藏/恢复、退群、解散与 Agent 只读观察。Prompt 默认预览前 2,000 字符，可展开全文或收起；Skill 展示完整正文，其他资源展示配置字段。
  资源删除需先检查并确认，仅删除所选资源；被引用的资源、仍托管的 Agent、
  默认 Prompt 以及损坏或悬空引用的配置会阻止删除。资源删除无法在 Web 撤销。
  Agent 卡片的“编辑角色”支持修改说明、模型、Prompt 引用和 Skills/MCP 挂载，
  下一次运行生效；共享 Prompt 正文、托管身份和策略不在此处修改。
  成员调整、归档及其他高级操作继续使用 CLI。
  新建 Skill 仅生成描述骨架，完整指令请用 CLI 完善。

## 开发与测试

```bash
cargo build -p agt-cli
node --test web/test/*.test.mjs
```

HTTP 测试包含真实 CLI 的隔离目录集成，使用 manual 策略，不调用付费模型。
前端是原生 HTML/CSS/JavaScript，服务使用 Node 核心模块，业务仍由 Rust CLI 实现。

可选浏览器验收（Node.js 22+、本地 Chrome，隔离目录和示例状态，不调用模型）：

```bash
node web/test/presence.browser.mjs
node web/test/workspace.browser.mjs
node web/test/mentions.browser.mjs
```

Chrome 默认 `/opt/google/chrome/chrome`，可通过 `CHROME_BINARY` 指定。

模型推理强度支持 `none / minimal / low / medium / high / xhigh / max`，也可选择
“Others · 其他（自定义）”填写 Provider 支持的新值。自定义值去除首尾空格后保存
并原样发送，不做预设枚举限制；是否支持由 Provider 校验。“不指定”省略参数，
与显式发送 `none` 不同。此选项不设置输出 token 上限。

Agent 团队使用“已启用／已停用”和“运行设置”。卡片支持多选、全选、批量启用与
批量停用，部分失败会逐项反馈并保留失败项选择。停用作用于该 Agent 的所有聊天
身份，保留配置、身份和历史；重新启用可能处理已有待处理消息。新配置默认启用，
老 bindings v1 数据库自动升级为 v2，已有绑定保持启用。

`agent_set_enabled` 是 Manager 或挂载资源管理能力的 Agent 可调用的统一工具（CLI/MCP 同样可用），参数是
`principal` 和 `enabled`。`agent_unbind` 仍表示解除运行配置；需要删除仍有关联
配置的 Agent 时，可在“运行设置”中解除。停用与群聊中的“停止本群 Agent”分开。

模型连接对 HTTP 非成功状态、连接/读取失败、无效 JSON、显式错误响应以及空回复
自动重试，总计最多 10 次（含首次）。等待从 250ms 指数增长，最多 4 秒；每次请求
仍受模型超时约束。重试沿用同一上下文，不重跑已完成工具，不额外消耗逻辑模型步骤。
调度调用计数按实际尝试累计，Run 调用详情记录 `request_attempts`，失败保留 HTTP
状态码和次数。回复与参与判断都适用；工具调用无正文或明确沉默不是空回复。
停止/停用会终止后续尝试，但已发出的请求是否取消或计费由上游决定。明确拒绝、截断、
配置错误和工具错误不按连接故障重试；失败 Run 的幂等回放不会重新执行整个任务。

单次任务不再设置模型调用轮数上限，父任务和委派子任务均可持续调用工具直至完成。
Web 不再展示此设置；旧 `max_steps` 字段和 CLI `--max-steps` 参数兼容读取但忽略。
仍保留实际调用计数、取消/停用、HTTP 最多 10 次尝试、上下文大小与单次工具批量限制。
群聊讨论的回复次数与有效期属于独立调度规则，不是本次取消的模型调用轮数限制。

## 上下文管理

在输入框单独输入 `/new`，按 Enter 或点击发送，即可打开重置确认框；命令不会作为消息发送，
不调用模型。也可使用会话信息 / 群信息中的“模型上下文 → 重置上下文”。确认后停止相关 Agent 工作，
清除该会话的 Agent 摘要；聊天记录保留，发送新消息后从新起点继续。仅人类私聊参与者、
人类群主 / 管理员可操作。历史查询工具仍可主动查阅旧消息，重置不等于删除或彻底遗忘。

长对话和长工具运行会自动摘要，调用配置模型并产生费用。新建模型可填写上下文窗口，
默认 272000；按 Provider 文档调整，已有模型可用 `agt model update <model> --context-window <tokens>`。
该值用于输入预算，不设置输出 token 上限。调试调用记录区分“上下文压缩”和普通模型调用。
详情见 [架构与语义](../docs/context-management.md)。

默认窗口对齐 Codex 回退值 272000；自动压缩阈值为 90%，有效窗口为 95%。
已有模型显式保存的窗口值保持不变；使用 `agt model update <model> --context-window 272000` 更新旧值。

## 实时生成预览

Chat Completions 与 Responses 请求现在使用 `stream: true`。会话底部显示独立、可折叠的
生成区域：准备、等待模型、模型处理、正文生成、工具准备/执行、Run 上下文压缩和重试。
没有公开正文时显示阶段与耗时；这里不会展示模型私有思考、加密推理、工具参数或工具结果。
会话历史压缩和参与判断仍显示已有的整体参与状态，不展示其内部输出。

正文预览保留最近 4 KiB，约每 300ms 更新运行快照；Web 根据 SSE 失效通知合并刷新，
并非逐 token 动画。草稿与正式消息分开，完成后才按原有投递规则发布；工具仍在响应完整、
整批验证通过后执行。断流沿用最多 10 次尝试，重试清除旧草稿，不拼接不同尝试的文字。
完成、失败或取消会清除草稿，保留公开工具活动与结束时间；停止讨论、重置上下文、退出和切换会话后隐藏旧任务草稿。
进程异常退出可能留下最后快照，但 Web 不展示已经失效的调度任务。

兼容忽略 stream 参数而返回普通 JSON 的 Provider，此时只能显示等待阶段，无法提前显示正文。
明确拒绝流式参数的 Provider 会按 HTTP 错误处理，不会自动改参数重发。
取消在流式内容事件之间检查；连接或读取阻塞且上游不发内容时，仍可能等到数据到达或请求超时。
已发送的上游请求是否停止计算或计费，由 Provider 决定。

## 工具执行卡片

运行摘要下面按调用 ID 展示工具卡片：执行中、成功、失败、取消或结果待确认。
并发操作分别更新，展开状态与键盘焦点保留；工具的公开结果摘要直接显示，点击展开工具标识、调用参数和执行结果。
运行结束后卡片可从后端记录重新加载，草稿不会作为历史保留。当前范围为最近 50 次 Run，
每次最多 40 项活动；这不是无限历史归档。未收到结束事件的工具显示“结果待确认”，不推测成功。

Native 和 Codex 共用公开卡片。命令、文件、Framework、MCP 通过 renderer 表分别展示，
不支持的工具回退到通用卡片。等待模型审核或人工审批显示独立摘要与现有审批入口；
命令原文、路径、diff、stdout/stderr、MCP 返回内容不进入群聊可见的活动投影。

模块边界：

- `activity.mjs`：后端会话/成员校验、实时与终态投影、字段白名单。
- `public/execution-view.js`：每个 Run 的摘要、生成预览、审批入口和视图清理。
- `public/tool-activity.js`：按活动 ID 更新工具 DOM、展开状态和耗时。
- `tool-details.mjs` / `public/tool-details.js`：独立校验与按需加载原始详情，不共享详情缓存。
- `public/tool-renderers.js`：按工具名/类型选择展示规则与通用回退。
- `public/execution-view.css`：运行摘要与工具卡片样式，沿用工作台颜色和字体。

SSE 仍只通知刷新；当前身份失去会话成员资格时不返回工具记录。切换身份/会话或刷新失败会清理旧数据。
卡片摘要展示公开事实。展开后，执行者身份或本机操作员可读取所属会话的原始详情，仍要求当前会话成员资格；其他成员仅可见摘要。
详情包括 Native 参数/结果、Codex 命令/工作目录/输出/退出码和执行器提供的文件变更 diff，按纯文本展示。
详情独立保存在 runtime 数据库 schema v6 的 `tool_details`，不进入 Run 快照、调用摘要、SSE 或消息历史。
每字段最多保存 64 KiB 并标明截断；旧记录或执行器未提供的内容显示不可用。结果在工具报告完成后更新，不实现终端逐字流。
本机 CLI 可通过 `agt run tool-detail <run-id> --activity <activity-id>` 查询同一记录。
这些查看入口不是审核权限的替代，也不向观察身份授予操作权限。

## 已解散群聊的历史入口

“最近会话”最多保留最近查看的 20 个已解散群聊入口，活跃会话不受影响。
超过后会显示“查看全部历史”提示；打开旧群的历史后，它会重新进入最近窗口。
查看顺序保存在本机数据库，刷新和重启保留；后台轮询不算查看。
未曾查看的旧群按会话更新时间初始化顺序。只读观察 Agent 不改变对方的查看记录。
这个窗口只限制 Web 列表展示，聊天记录完整保留，不会自动删除或释放磁盘空间。

## 协作界面与快捷操作

工作台采用参考飞书的浅灰 / 白色面板、蓝色强调色和紧凑排版，保留 AGT 的身份与执行状态。
会话列表搜索框可同时搜索当前列表中的会话，以及工作空间中的用户 / Agent 名称和 ID。
点击联系人直接打开私聊：复用已有会话、恢复隐藏入口；已归档会话使用原有确认恢复流程。
搜索与打开私聊不发送消息、不调用模型。观察 Agent 身份时不显示联系人发起私聊入口。

右键会话或点击行尾“⋯”，可打开会话、查看会话 / 群信息、从列表移除。
菜单支持方向键、Home / End、Escape，也可通过 Shift+F10 打开；触屏使用“⋯”。
移除仍需要确认且仅隐藏入口。退出和解散仍在群信息中，保留权限检查与确认。
只读观察菜单只提供打开和信息查看，不代替 Agent 修改会话。
本轮未加入置顶、消息全文搜索或消息右键操作。

## 整理 Agent 会话

在“Agent 会话”中选择身份，点击列表上方“整理会话”，可多选当前搜索结果（每次最多 100 个），
批量“移除所选”或“恢复所选”。列表新增“已移除”筛选。确认框显示目标身份及数量，
部分失败逐项反馈，失败项保留选中。搜索可先缩小整理范围。
这项管理操作仅改变目标 Agent 的个人入口；消息、成员、上下文和任务不变。
Agent 仍在会话中时，新消息会使隐藏入口重新出现。此功能不永久删除共享群聊历史。
观察页仍不能替 Agent 发言，整理入口是独立、受限的管理操作。

工作区交互优化：大屏聊天区适配窗口高度，列表、消息和成员状态分别滚动。
成员状态默认使用紧凑行，展开查看判断原因；Agent 卡片不再因旁边卡片展开而一起拉长。
在会话页按 Ctrl/⌘+K 可展开并聚焦搜索，搜索框支持一键清空。
输入框随内容增高并限制最大高度，阅读旧消息时可点“回到最新消息”。
手机上选择会话后收起列表，点击标题旁“‹ 会话”返回列表，草稿保留。

## Harness 资源与 Codex 会话

资源库 → Harness：分别创建后端开发、文档维护等运行配置，填写名称、说明、服务器上的
Codex 可执行文件、项目目录、默认模型/档位和文件权限。保存后可“读取可用模型”，
“检查连接”不发起模型推理。“执行会话”列出自己可见聊天中的关联记录。
先在运行 Web 的同一服务器账号下完成 `codex login`；自定义 Provider 沿用 Codex 配置。

创建/编辑 Agent → 执行方式 → 外部 Harness，选择已有资源，无需创建 AGT Model。
外部 Agent 支持私聊及群内 @，自动发布最终答复，支持流式预览、停止与 `/new`。
角色 Prompt、Skills 正文和内置资源管理工具可用；AGT MCP 挂载、显式委派名单、
交互审批仍不支持。Codex 自己的 MCP/Skills 可通过命令查询。

已有会话保存自己的配置快照。修改 Harness 默认配置只影响新会话；`/new` 之后采用新默认值。
首次执行返回的默认模型/档位会固定到会话快照，Session ID 由 Codex 生成，AGT 不生成或编辑。
同一个工作目录中的文件和运行账户的 Codex 配置仍会共享；如需文件隔离，请配置独立目录。
Harness 使用 `harnesses/` 目录、`harness.yaml` 和 Agent 的 `harness` 引用字段。
旧 environment 类型、字段和目录不再读取，不做数据迁移。

输入区“/ 命令”提供：

- `/model`：群聊先选 Agent，读取真实模型/思考档位，选择后仅影响该 Agent 在本聊天的后续执行。
- `/status`、`/permissions`：查看执行会话的目录、模型、Session ID、文件权限等快照信息。
- `/rename`：设置 Codex 会话名称，不修改聊天名称。
- `/compact`：确认启动压缩，等待实际完成；可取消。可能调用模型。
- `/skills`、`/mcp`：读取当前 Harness 项目的 Codex Skills 与 MCP 服务器状态。
- `/new`（`/clear`）：重置上下文；`/stop`：停止本轮 Agent 执行；`/help`：命令帮助。

命令不作为普通消息发送，未知命令和参数明确提示；讨论命令文字可输入 `//model`。
`/review`、`/diff`、导入已有线程、`/resume`、`/fork` 和交互审批尚未接入。
失败/中断后检查运行记录和项目文件，再使用 `/new` 重新开始；不会自动重试未知结果。
重置保留聊天记录，不删除 Codex 的长期记忆或项目文件。
后端 CLI 及模块边界详见 [Harness 接入设计](../docs/harness-integration.md)。

## 权限处理模式

审批列表和详情顶部可保存工作空间权限模式，关闭页面后仍持续生效。
Native 支持模型审核（异常转人工）、人工审批、自动放行；Harness 支持人工审批和自动批准引擎提供的本次/本回合权限请求。
模式对当前等待及后续请求生效，不撤回已作出的决定，不改变 Codex 沙箱范围。
只有控制台操作者可修改，Agent 观察身份只读。配置使用版本比较保存，避免覆盖其他窗口的修改。
模式面板由 `public/permission-mode.js` 管理；一次性的“一键全部通过”已移除。

已完成、取消、失败等非运行中执行提示可通过右侧关闭按钮隐藏。关闭状态按浏览器、身份和会话保存，刷新后仍生效；不会删除后端执行记录，也不会隐藏重新进入运行状态的执行。
