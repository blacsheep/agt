# AGT Studio · 本地交互控制台

无需安装前端依赖。需要 Node.js 22+、Rust，以及本仓库构建出的 CLI。

## 启动

在仓库根目录执行：

```bash
cargo build -p agt-cli
node web/server.mjs
```

打开终端打印的**完整链接（包括 `#` 后的令牌）**。默认端口 4317，读取
`~/.agt`；首次启动会创建 `web-operator` 用户身份，不会自动调用模型。
已有资源不会被启动流程覆盖。服务器重启后，请使用新的完整链接。

可选择隔离的资源目录或其他端口：

```bash
node web/server.mjs --home /absolute/path/to/test-home --port 4318
```

`--binary /absolute/path/to/agt` 可指定其他 CLI，`--principal my-operator`
可指定本地用户身份。空目录会初始化；不要把正式目录当作无副作用的演示环境。

## 自己验收：准备 → 对话 → 执行 → 观察

1. **资源库准备模型**：已有 Provider 会直接列出。若模型标注为
   Responses，创建一个新的模型别名，选择 Provider，填写 Provider 实际支持的
   模型名称。当前运行时只支持 Chat Completions；别名不会转换 Provider
   的协议，Provider 本身必须支持该接口。不要覆盖原有模型。
2. **Agent 团队创建角色**：选择模型、填写职责 Prompt，按需挂载 Skills/MCP。
   默认策略为“私聊 / 群内被提及”。可创建主持人、研究员、反方等通用角色，
   没有游戏专属层。创建失败会显示已完成步骤；已创建字段锁定，后续步骤可修正重试。
3. **新建会话**：私聊选择一位参与者；群聊选择多位参与者。群消息广播给成员，
   勾选“邀请回应”控制 mentions；是否实际执行还取决于各 Agent 的响应策略。
4. **发送任务**：消息先保存并进入收件箱，不会立刻产生模型费用。
   Prompt 中建议明确如何使用 IM 工具、何时回复以及何时输出 `[[silent]]`。
5. **执行一批**：点击右上角按钮，检查付费警告后确认。每批数量是
   **每位 Agent 的投递上限**，执行范围是当前 home 的**所有托管 Agent**，
   不是仅当前会话。默认每次运行最多 8 个模型步骤、自动消息深度 3。
6. **查看结果**：消息下方“查看投递”检查处理状态；运行观察中查看 Run 和调用记录。
   切换“查看身份”可以只读观察 Agent 的会话，不会代替它发送消息。
   新产生的消息可能需要再次执行一批；阶段推进仍由你组织。

第一次可把角色策略设为“不自动回应”，验证发消息和投递的 skipped 状态，
确认操作熟悉后再改为“私聊 / 群内被提及”。已跳过的消息不会因修改策略自动重放，
请发送一条新消息测试真实模型。

## 安全和当前范围

- 这是**可信本机管理控制台**，不是多用户登录系统。令牌持有者能管理资源和
  观察不同身份的私聊；不要分享链接、代理到公网或交给不可信网页使用。
- 服务仅监听 `127.0.0.1`，校验 Host、Origin 和 API 令牌；通过参数数组调用
  CLI，不拼接 shell 命令。Provider 列表不显示密钥；创建 Provider 使用服务
  启动前设置的环境变量名，页面不接收密钥原文。
- MCP 需要绑定授权和执行批次授权。只挂载可信 MCP，它可能访问文件、网络或外部系统。
- 同一服务进程只允许一批 worker；不要对同一 home 同时启动多个控制台或 CLI worker。
  批次状态只保存在服务进程内，Run/消息记录由后端持久化。
- 没有后台无限循环调度。关闭服务会中断子进程，可能留下结果不确定的
  `started/running`；先使用 CLI 检查，再决定是否重试，不能假定外部操作未发生。
- `completed` 只表示运行结束，不保证所有工具成功或目标达成。调用记录仅包含
  参数形状和安全错误，不包含模型推理、原始参数或工具返回正文。
- 当前页面支持新建资源/角色、更新或停止托管、私聊/群聊与观察。
  现有角色资源编辑、成员调整、归档及其他高级操作继续使用 CLI。
  新建 Skill 仅生成描述骨架，完整指令请用 CLI 完善。

## 开发与测试

```bash
cargo build -p agt-cli
node --test web/test/*.test.mjs
```

HTTP 测试包含真实 CLI 的隔离目录集成，使用 manual 策略，不调用付费模型。
前端是原生 HTML/CSS/JavaScript，服务使用 Node 核心模块，业务仍由 Rust CLI 实现。
