# Contributing to agt

## Build and test

You need Rust 1.96.1 or newer. The Web console tests also need Node.js 22 or newer; `agt` itself does not.

```bash
cargo build -p agt-cli              # target/debug/agt
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
node --test web/test/*.test.mjs     # runs target/debug/agt web
node --test --test-concurrency=1 web/test/*.browser.mjs   # needs Chrome
```

No test needs a model API key. The web tests need Node.js 22 or later; the console itself does not. The browser tests drive the console in headless Chrome at `/opt/google/chrome/chrome`; set `CHROME_BINARY` to use another path, and `AGT_DESIGN_CAPTURE=1` to save screenshots under `/tmp`. CI runs all of these. See [Web console architecture](docs/zh/architecture/web-console.md) (Chinese).

To run the console from your working tree:

```bash
cargo run -p agt-cli -- web
```

## Where tests go

- Short unit tests go in the file they test, in `#[cfg(test)] mod tests {}`.
- Longer unit tests that need private items go in `<module>/tests.rs`, split into `<module>/tests/<topic>.rs` by topic. Declare them with plain `mod`; do not use `#[path]` or `include!`.
- Integration tests that only use the public API go in `crates/<crate>/tests/`: one file as `<suite>.rs`, or several as `<suite>/main.rs` with submodules. They do not reach into `src/`.

## Crates

```text
agt-core       shared IDs, categories and typed references
agt-storage    safe filesystem access, shared SQLite connections, local wakeups
agt-config     home directory layout and initialization
agt-provider   OpenAI-compatible providers
agt-model      model aliases that reference providers
agt-prompt     PROMPT.md resources, including the built-in default and lead prompts
agt-skill      SKILL.md resources (scoped packages supported)
agt-mcp        mcp.json resources (stdio and HTTP servers)
agt-agent      agent.yaml: model or harness, prompt, skills, MCP servers
agt-harness    harness resources, the Codex protocol and execution control
agt-im         participants, direct and group chats, messages, roles, read state (SQLite)
agt-service    tool service, identities and permissions, agent bindings, stdio MCP server
agt-inference  agent resolution, model protocols, streaming, context budget and compaction
agt-runtime    model/tool loop, persistent runs, delivery scheduling, delegation
agt-cli        the agt command-line interface, with the Web console built in
```

The Web console is a page in `web/public/` (plain HTML, CSS and JavaScript, no build step) and a server in `crates/agt-console/` that turns each request into an `agt` command; `agt web` serves it over HTTP and the desktop app calls it in-process. `crates/agt-console/build.rs` embeds the page into the binary, so a change under `web/public/` reaches `agt web` after a rebuild. Server tests in `web/test/` start `agt web` with a scripted CLI (`web/test/support/`).

### Console text

Write console text in Chinese and wrap it in `$t()`; the Chinese text is the message key. Values go in as arguments, not by joining strings, so each language can order the sentence:

```js
$t('已载入 {0}/{1} 个会话', [loaded, total])
```

Add the English to `web/public/locales/en.js`. For counts, use a plural form there: `'{0, plural, one {# message} other {# messages}}'`. Write one message per case instead of passing a word such as a verb in as an argument. In `index.html`, mark text with `data-i18n` and translated attributes with `data-i18n-attr="title aria-label"`. Text that the server or the CLI sends to the page is translated where it is shown, so it needs an entry too.

`node --test web/test/i18n.test.mjs` fails when a key has no English or when Chinese text in the console is not wrapped. Messages, prompts and tool output come from people and agents and are never translated.

## Documentation

User docs live in `docs/` and are published with VitePress. Every page under `docs/guide`, `docs/modules` and `docs/help` has a Chinese counterpart under `docs/zh/` with the same file name and sections; change both in the same commit. Write each paragraph and list item on a single line; a line break inside a paragraph shows up as a space, which breaks Chinese text. Diagrams are SVG files generated by the scripts in `docs/diagrams/`; change the script and run `python3 docs/diagrams/build.py` instead of editing the SVG. Check the site builds and has no dead links:

```bash
cd docs && npm ci && npm run build
```

## Releasing

Releases are built by [dist](https://opensource.axo.dev/cargo-dist/), configured in `dist-workspace.toml`. To publish version `X.Y.Z`:

1. Set `version` in the workspace `Cargo.toml` and in `CITATION.cff`, and add a `## X.Y.Z - <date>` section to `CHANGELOG.md`; the release notes are taken from it.
2. `main` only accepts pull requests that pass CI, so open a pull request with these changes and merge it.
3. Tag the merged commit and push the tag: `git checkout main && git pull && git tag vX.Y.Z && git push origin vX.Y.Z`.

The Release workflow builds every platform, the installers and the checksums, and publishes the GitHub Release with the `GH_RELEASES_TOKEN` secret. Do not edit `.github/workflows/release.yml` by hand: change `dist-workspace.toml` and run `dist generate`.
